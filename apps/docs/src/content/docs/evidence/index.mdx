Every claim in these docs that says "live" points here. Each transaction links to Cardanoscan
(preprod); blocks, fees, times and the details under "What to check" were read back from the chain.
Nothing on this page is simulated, and no hash is filled in before its run has happened.

:::note[How to read the numbers]
Fees are what the chain charged. Latency is wall-clock time from the agent's request to the stated
point and includes the human passkey approval, which dominates it. Preprod ADA (tADA) has no value.
:::

### Auto-pay: the agent paid with no tap, limits enforced by Cardano

The same contract, this time from the app and the user's own passkey wallet
`addr_test1vqj6…3wa`. In the agent's **Auto-pay on Cardano** screen the user set $5 per payment
(25.943985 ADA at creation) and a daily cap of 103.77594 ADA, and approved the create with one
passkey tap. Sixteen minutes later ChatGPT bought the address report on the direct x402 route and
nothing reached the phone.

<ExplorerChecks id="autopay-create" />

<ExplorerChecks id="autopay" />

The payment spends output `#0` of the create (the allowance) and its output `#1` (the agent's
float). Off chain, ZyroPay recorded request `01a1913d-6fe7-7bd5-9b24-def768ce6540` with policy
decision `allow`, reason `AUTO_PAY_ALLOWANCE`, state `CONFIRMED` and no approval record, and the
seller's signed delivery receipt verified against `addr_test1qr954…kaen`. The limits were not
ZyroPay's to enforce: the validator (script `fe651537…1aeb`, executed in this transaction)
accepted the spend only because the 2 ADA went to a listed payee, stayed under the per-payment
maximum and the day's cap, and the continuing output carries the datum with `spent_in_period`
raised by exactly 2 ADA. The agent key is held encrypted by ZyroPay's API, one per allowance;
what it can spend is bounded by that datum until the user revokes. Revoke from the app has not
run live yet.
