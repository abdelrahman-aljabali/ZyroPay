# Third-party brand assets

ZyroPay shows other companies' logos only to **identify** a chain, token or integration
(nominative use). It never claims a partnership or endorsement: copy stays factual
("Connect with Claude", "Jupiter", "Base"), with no "official", "partner" or "certified"
wording anywhere.

All assets were fetched from official brand kits or official GitHub
organisations only. Where a brand's rules forbid this use, or no official file could be
obtained, the app keeps a **neutral mark** (an initial, a monogram or a category icon).
It never shows a redrawn imitation.

Each brand's rules are quoted below. Treat those quotes as the reference. The notes on how
ZyroPay applies them are engineering judgement, not legal advice. Get a legal review before
a production launch, and re-check the sources whenever a brand updates its kit.

## How the assets are stored

- `packages/ui/src/brand/svg/*.svg` holds the source files. Each one is the official file,
  passed through SVGO 3.3.2 with:
  - the multipass default preset, keeping the viewBox;
  - dimensions removed;
  - inline styles converted to attributes (react-native-svg ignores `<style>`);
  - ids prefixed per file, so gradients from different logos on one web page cannot
    collide.

  Geometry and colours are unchanged. The SHA-256 of each original download is recorded in
  the tables below.

- `packages/ui/src/brand/svgs.generated.ts` is generated from those files by
  `node packages/ui/scripts/brand-svgs.mjs`.
  - The generator rejects scripts, raster `<image>`, `foreignObject`, event handlers and
    external references.
  - `pnpm --filter @zyropay/ui test` runs it with `--check`, so a stale bundle fails CI.
- The marks render through `BrandMark` (react-native-svg `SvgXml`). It scales them
  uniformly, so they stay sharp at 1x to 3x and are never stretched, cropped or animated.
  - Chain and token marks: `NetworkLogo`, `TokenLogo` and `AssetLogo` in
    `packages/ui/src/icons/CryptoLogo.tsx`.
  - Plugin marks: `PluginLogo` in `packages/ui/src/brand/PluginLogo.tsx`.
- Light and dark variants: a mark sits on a plain round plate (chains) or a rounded tile
  (plugins).
  - The plate or tile is white in light mode and the dark surface colour in dark mode.
  - On each background the mark uses the variant its brand ships for that background.
  - A brand with no dark-background variant keeps a white plate in dark mode. The app
    never recolours a mark.
- All logos are decorative for accessibility (hidden from screen readers). The row or card
  around a logo already names the brand.
  - Exception: the plugin detail header's logo is a link to the project's website, labelled
    "<Plugin> website".

To add or replace a mark:

1. Download the official file.
2. Run SVGO with the settings above.
3. Drop the file into `svg/`.
4. Run the generator.
5. Add a row to this file with the source, date and rules.

- the rules below;

## Onboarding orbit (decorative)

`components/marketing/chain-marks.ts`) shows 20 well-known chains around the ZyroPay mark. It
is an illustration of "the wider crypto world" and is hidden from screen readers. It is not
a list of supported networks, and nothing functional reads it. The earlier version drew flat
approximations of each chain's mark. Those were imitations and have been removed.

plate (the same plates as the chain marks above), or a neutral monogram. The motion is
unchanged: about one revolution every 1.5–3 minutes, and fully static under Reduce Motion.

networks and the networks planned next. Same policy as above: official files only, nominative
use only, a plain monogram where no usable official mark exists. The files live in
`apps/landing/public/brand/networks/` and the list in `apps/landing/src/lib/networks.json`.

- The four live networks reuse the files above (`solana.svg`, `ethereum-on-dark.svg`,
  `base.svg` on a white plate, `cardano-on-dark.svg`).

  `style="stop-color:…"` (Bitcoin) were converted to presentation attributes, because WebKit
  applies the page's strict CSP to SVG images. Geometry and colours are unchanged.
- For zip sources the hash in the File column is of the extracted SVG; the zip's own hash is in
  brackets in the Source column.
